# Skill: job-evaluation

## 目的

候補者のプロフィールと希望条件をもとに、求人票を多角的に評価し、
マッチ度スコアとその根拠を出力する。

## どんな時に使うか

- 複数の求人を候補者に合わせてランキングしたいとき
- 求人票を見て「この人に合うか」を判断したいとき
- 候補者へのマッチング理由を言語化したいとき

## 必要な入力

| 入力 | 必須 | 説明 |
|------|------|------|
| Candidate Profile | 必須 | スキル・職歴・インサイト・マッチング軸を含むJSON |
| Preferences | 必須 | 希望職種・勤務地・年収・重視条件などのJSON |
| Job | 必須 | タイトル・会社名・業務内容などの求人データ |
| Feedback Memory | 任意 | 過去に気に入った/気に入らなかった求人のパターン |

## 評価の手順

1. **Must-have確認**: 希望条件の絶対条件（雇用形態・勤務地など）を最初に確認する。
   該当しない場合はスコアを低く設定し、以降の詳細評価は不要。
2. **各観点のFitを評価**: 下記の評価観点を順番に検討する。
3. **Feedback Memoryの反映**: 過去のフィードバックがあれば、そのパターンをスコアに反映する。
4. **総合スコアを決定**: 各観点の評価を統合して1〜10点を出す。
5. **根拠を言語化**: なぜそのスコアになるかを1〜2文で説明する。

## 評価観点

### 1. Must-have条件
- 雇用形態（正社員/業務委託など）が希望と一致するか
- 勤務地・リモート条件が希望と一致するか
- 明確な除外条件（避けたい条件）に該当しないか

### 2. 職種・仕事内容とのFit
- 希望職種に近い業務内容か
- 日々の仕事の種類（開発 / マネジメント / 企画 / 営業 など）が希望と合うか

### 3. スキル・経験とのFit
- 求人の必須スキルをプロフィールが満たしているか
- 歓迎スキルにどの程度合致するか
- 経験年数の要件を満たしているか

### 4. キャリア方向性とのFit
- プロフィールの「一貫しているキャリアの軸」と求人の方向性が一致するか
- この求人がキャリアの次のステップとして自然かどうか
- 成長・学習の機会があるか

### 5. 希望条件とのFit
- 希望年収の範囲内か（情報がない場合は不明として扱う）
- 希望する企業規模・フェーズに合うか
- 重視条件（技術力・裁量・WLBなど）が求人に含まれているか

### 6. 志向性とのFit
- プロフィールの「向いていそうな環境・文化」と求人の文化が合うか
- 0→1フェーズ / 拡大期 / 安定期 など、好む会社フェーズに合うか
- 裁量度・自律性の高さが希望に合うか

### 7. 懸念点
- プロフィールの「避けた方が良さそうな環境」に該当しないか
- Feedback Memoryで気に入らなかったパターンに近くないか
- 明らかなミスマッチはあるか

### 8. 求人票だけでは判断できない確認事項
- 評価に必要だが求人票から読み取れない情報を特定する
- 例: 「リモート比率が不明」「チーム規模・構成が不明」「使用技術スタックが不明」

## 不明な情報の扱い

- 求人票に給与情報がない場合: 給与条件での減点はしない。別途確認事項として記録する。
- 求人票の業務内容が薄い場合: 判断できる情報だけで評価し、評価不確実性をコメントに示す。
- プロフィールに情報がない項目: そのポイントは評価対象外として扱い、他の観点で総合判断する。

## Match Scoreの考え方

| スコア | 意味 |
|--------|------|
| 9〜10 | 強くお勧めできる。ほとんどの観点でマッチしており、懸念点がほぼない。 |
| 7〜8  | お勧めできる。主要な観点でマッチしており、軽微な懸念点がある程度。 |
| 5〜6  | 部分的にマッチ。いくつかの観点でズレがあるが、試してみる価値はある。 |
| 3〜4  | あまりお勧めできない。主要な観点で複数のミスマッチがある。 |
| 1〜2  | お勧めできない。Must-have条件を満たさない、または大きなミスマッチがある。 |

スコアは「完璧な求人は存在しない」という前提で付ける。
5点が「普通」ではなく、「希望条件との合致度の相対評価」として使う。
同じ求人群の中でのランキングに使われるため、分散を意識してスコアをつける。

## 注意事項

- 求人票の文章が魅力的でも、プロフィール・希望条件との一致度を優先する。
- 有名企業・高年収だからといって自動的に高スコアにしない。
- Feedback Memoryがある場合は必ず反映する。ない場合はプロフィールと希望条件だけで判断する。
